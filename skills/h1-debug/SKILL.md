# H1 真机调试

让 AI 编写程序后，通过已有 H1Debug 驻留服务上传代码与数据、操作真实设备并保存可核对的结果。用户要求更新或迭代目标程序时，上传新版属于正常工作；不要把保留无关状态误解成禁止更新。复用兼容的H1Debug服务，不因目标程序改动就重装调试器。

## 找到实际工具与设备

先在当前仓库、用户指定的工具根目录中查找 `tools/h1_debug.py` 和 `h1-debug/README.md`，以共同父目录作为 **H1工具工作区**。本 skill 随 `BBKH1-debug` 仓库发布；若仍位于该仓库的 `skills/h1-debug`，仓库根就在上两级。被复制到个人 skills 目录后，该相对关系不再成立，应查找已有工具 checkout，不把 skills 目录当工具根，也不创建同名空目录冒充依赖。

确认需要的 `dist/H1Debug.build.json`、SDK或编译器是否存在；源码 checkout 未必自带 release 产物。缺少依赖时按找到的仓库 README 获取对应 release 或构建。当前项目是其他 BDA 时引用这个工具工作区，保持业务源码及输出位置明确；所有下文工具路径均相对于它。不假设用户名、盘符、Python安装位置或设备端口。

读取当前 README、构建摘要及与本任务有关的代码；本 skill 的历史地址、结果不能覆盖更新后的源码和设备观测。PC 工具已有协议、校验、枚举与模块编译逻辑，优先复用，避免另写串口协议。

- 日常测试目标 BDA、截图、输入、内存和 EXEC，读取 [operations.md](references/operations.md)。
- 更新完整 BDA、管理设备文件/目录、刷新桌面和运行新版，读取 [deployment.md](references/deployment.md)。
- 修改/安装 H1Debug、诊断 USB/CPU调频掉线、恢复连接或验证驻留生命周期，读取 [maintenance.md](references/maintenance.md)。

设备仅绑定 **H1/Y100 V1.41**。调试 USB 为 `07C4:A4A6`，普通磁盘为 `07C4:A4A5`，握手必须精确为 `H1DEBUG/1 V1.41 RESIDENT`。用客户端 `list` 发现当前端口；COM4、F:、G: 都只是历史实例。有多个匹配设备或身份不符时先区分目标。

## 关键选择

- **按更新对象选择命令**：完整普通 BDA 用 `deploy LOCAL.bda 'A:\应用\程序\NAME.bda'`，仅传文件用 `file put/get`，文件管理用 `file list/delete/rename/mkdir/rmdir`，已确认的 RAM 代码/数据用 `write`，测试模块用 `exec run SOURCE`。完整 BDA 走原生文件系统和载入器；EXEC 接受独立 `h1_module_entry` ABI。先核对当前驻留 CAPS：bit9 文件事务、bit10 桌面控制、bit11 文件管理，旧版 `0x1FF` 均不支持。2026-10-17的`4214dbc...`构建已真机验证不拔线部署、文件管理、后台测试、DTR重开及再次打开H1Debug关闭；用户确认后拔插恢复磁盘，详情见维护页。
- `deploy`、`desktop refresh/run` 要求先正常退出前台 BDA、回到空闲原生桌面；客户端不会自动按 ESC。`deploy --no-run` 会上传并刷新，但不运行。更新普通目标 BDA 不需重装调试器；更新 H1Debug 自身后仍须重启设备，不能靠重新运行自身热升级。
- 默认截图保持 **480×272**，自动使用设备支持的无损 RLE；不要用96×54预览替代截图质量验收。预览还会替换 EXEC 模块，不是无副作用的截图捷径。
- 端口仅由一个会话持有，RPC 串行执行。需要连续输入、快照下载或测试模块时复用一个 `Client`；代理之间并行做离线分析，不并行操作同一 H1。DTR变化会废弃快照token、请求取消活动EXEC、未完成文件事务和目录游标；清理由worker继续执行。桌面job不随DTR关闭取消。不要跨独立CLI保留快照/目录token或拆开文件传输。
- 关闭调试只在桌面job的QUEUED/LOADING阶段返回BUSY；普通BDA已RUNNING时可停止后台而让前台继续。同版H1Debug再次运行也可关闭，CDC消失后不要盲重发启动/停止或点击；停止与恢复磁盘的确认见 [maintenance.md](references/maintenance.md)。
- 点击/按键 ACK 是事件已接受，不能等同于前台已完成绘制。桌面刷新DONE和`menu_idle=1`也可能早于屏幕重绘；短暂让前台调度后再截取新快照，不能用立即捕获的旧画面判定刷新失败。菜单坐标以当前截图为准。
- RAM 写入针对已识别的目标数据或模块明确拥有的分配。通用内存验收用现有工具新分配512字节、恢复后释放，不猜空闲地址。模块有活分配时，先运行它的清理入口再替换模块。
- EXEC 没有内存隔离、异常恢复或强制抢占。长任务定期 `api->poll_cancel()`；预算和 `cancel` 不能终止不协作死循环。失步/超时后保存结果未知的证据，不盲目重发写内存、执行或触控命令。
- CAPS bit12提供保留USB诊断，bit13提供调频失步的软件重新枚举。旧串口句柄失效后重新发现设备并握手，先核对原驻留/模块身份并读取保留结果；这不等于服务重启，也不代表可以自动重发命令。具体判断及真机验证范围见维护页。

## 验证与交付

根据改动选择验证范围，不把整套调试器验收套到每次业务 BDA 的小改动。区分主机/控制器模型、完整固件模拟器、实际物理 H1。模拟器通过不能证明真实 USB 速度；成功截图也不能单独证明所有按键或内存写入都正确。

保留实际测试的 BDA SHA256、驻留 image_id（版本有疑问时核对）、原尺寸截图、命令结果、耗时口径和内存清理状态。性能测试分别报告设备原始 tick 与 PC 往返时间；`tick_80hz` 是 ABI 旧字段名，不代表当前频率。

仅在用户要求安装或硬件测试的范围内操作设备；沿用当前会话已有授权，不逐条重复确认。确需用户手动重启、拔插或看关闭提示时，说明 PC 无法完成的具体原因并合并必要步骤。结束时说明调试是否仍运行、是否已关闭并恢复磁盘；不要为了套流程擅自切换用户需要保留的状态。
